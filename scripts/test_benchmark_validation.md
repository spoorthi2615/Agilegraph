# Benchmark Validation Protocol

This document outlines the testing protocols established in Sprint 79.2 to guarantee the scientific integrity, fairness, and reproducibility of the AgileGraph baseline benchmarking matrix.

## 1. Metric Consistency Test
1. Load the raw logits and ground truth labels generated by the `scripts.run_benchmarks` output payload.
2. Manually execute `sklearn.metrics.classification_report(y_true, y_pred)`.
3. **Verify**: The manually calculated Precision, Recall, and F1-Score mathematically match the numbers published in the `research/benchmark-study.md` Results Table.
4. **Why**: Eliminates the possibility of accidental (or intentional) rounding errors or favorable threshold manipulations in the reported metrics.

## 2. Configuration & Split Parity Test
1. Extract the PyTorch `DataLoader` objects utilized by the CodeBERT baseline, the GCN baseline, and the AgileGraph model during their respective evaluation loops.
2. Evaluate the `dataset.indices` array for each loader.
3. **Verify**: The exact same repository UUIDs must map to the Test Split across all models. 
4. **Why**: If a baseline model was evaluated against a fundamentally easier subset of the dataset than AgileGraph, the comparative results are scientifically invalid. This test guarantees absolute parity.

## 3. Seed Determinism Test
1. Re-run the AgileGraph benchmark loop locally using `--seed 42`.
2. Delete the PyTorch checkpoint and clear the GPU cache.
3. Re-run the AgileGraph benchmark loop again using `--seed 42`.
4. **Verify**: The final F1-Score across both distinct runs must match exactly to the 4th decimal place.
5. **Why**: Non-deterministic hardware acceleration (e.g., cuDNN auto-tuning) can introduce severe variance. Fixing the seed proves that the reported metrics are reproducible globally.

## 4. Error Analysis Validation
1. Extract the top 100 False Positives generated by AgileGraph from the benchmark logs.
2. Cross-reference the source AST graphs for these nodes.
3. **Verify**: Validate the documented limitation regarding "Dead Code". Confirm that a statistically significant portion of these False Positives are indeed isolated components (imports or deprecated methods) that lack active execution edges within the graph.
